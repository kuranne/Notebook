# Style & Language Standards

## 1. Zero-Emoji Mandate
- Emojis are strictly prohibited across all notes, documentation, configuration files, rules, and commit messages.
- Do not use decorative Unicode pictographs or emoticons.
- Represent alerts, status, and tags using plain markdown syntax or bracketed text:
  - Allowed: `[INFO]`, `[WARN]`, `[FAIL]`, `[PASS]`, `> [!note]`, `> [!tip]`, `> [!warning]`.
  - Prohibited: all Unicode emoji code points (U+1F300-U+1FAFF, U+2600-U+27BF, etc.).

## 2. Language Purity & Single-Language Policy
- Never append parenthetical translations or dual-language glosses (e.g. `Term (Translation)` or `Word (คำแปล)`).
- Strictly adhere to one language per heading, title, or statement:
  - Technical & CS courses: Use English exclusively for note titles, headings, code comments, and technical summaries.
  - Humanities & Thai-taught courses (e.g. HS369, PY252, TU courses): Use Thai or English consistently per note without mixed parenthetical duplicates.
- Preserve existing student writing tone and vocabulary; do not sanitize authentic personal study idioms.

## 3. Density & Conciseness
- Deliver high-density, concise text without conversational filler, preambles, or redundant meta-commentary.
- Standard technical abbreviations are encouraged (e.g. ISA, ALU, OS, DB, OOP, DS, DFS, BFS, FP, CI/CD, SHA, AST).
- Prioritize bullet points, key-value definitions, tables, and code snippets over narrative paragraphs.
